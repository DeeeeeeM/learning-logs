# 0. Setup VM and Network

- Open VirtualBox → Kali VM → Settings → Network → Adapter 1
    
- Check Enable Network Adapter - Attached to: NAT - Check Cable Connected
    
- Go to Adapter 2 and configure it as Host-only Adapter.
    
- Save the settings and start Kali.

After restarting Kali, run:
```bash
ip a
```

Check whether `eth0` now shows `LOWER_UP`.
If it does, request an IP address using DHCP:
```bash
sudo dhclient -v eth0
```

Test connectivity:
```bash
ping -c 4 8.8.8.8
ping -c 4 google.com
```
## 1. Nmap — Network Scanning

Nmap (Network Mapper) is a tool used to discover hosts, identify open ports, detect services, and gather information about network devices.

### 1.1 Host Discovery

Identify active hosts on a network without performing a port scan.

```bash
nmap -sn <ip-address>
```

### 1.2 Service and Version Detection

Identify services running on open ports and their versions.

```bash
nmap -sV <ip-address>
```

### 1.3 Operating System Detection

Attempt to identify the operating system of target hosts. Requires sufficient privileges and may not always identify the exact OS.

```bash
nmap -O <ip-address>
```

### 1.4 Aggressive Scan

Collect several types of information in a single scan.

```bash
nmap -A <ip-address>
```

### 1.5 Scan a Specific Port

Check a specific port and identify its running service.

```bash
nmap -sV -p 80 <ip-address>
```

- `-p 80` — Scan port 80 (commonly HTTP).

### 1.6 Scan All TCP Ports

Scan all 65,535 TCP ports on a target.

```bash
nmap -sV -p- <ip-address>
```

- `-p-` — Scan ports 1–65535.

## 2. Saving Nmap Scan Results

Nmap supports multiple output formats for storing scan results.

### 2.1 Normal Outpu `-oN`

```bash
nmap -sV -oN scan_result.txt <ip-address>
```

### 2.2 XML Output `-oX`

```bash
nmap -sV -oX scan_report.xml <ip-address>
```

### 2.3 Multiple Output Formats

Save results in multiple formats using one command.

```bash
nmap -sV -oA scan_result <ip-address>
```

- `-oA` — Generate normal, XML, and grepable output.
    
- The output files use the specified base name.

### 2.4 Convert XML to HTML

Convert Nmap XML output into a browser-readable HTML report using `xsltproc`.

```bash
xsltproc -o report.html /usr/share/nmap/nmap.xsl scan_report.xml
```

- `xsltproc` — XSLT processor.
    
- `-o report.html` — Specify the output file.
    
- `nmap.xsl` — Nmap's report stylesheet.
    
- `scan_report.xml` — Input XML file.

## 3. FTP — File Transfer Protocol

FTP is a protocol used to transfer files between a client and a server.

### 3.1 Connect to an FTP Server

```bash
ftp <ip-address>
```

### 3.2 Try Anonymous Login

Some FTP servers allow anonymous access.

```text
Username: anonymous
Password: anonymous
```

Access depends on the server's configuration.

### Useful FTP Commands

| Command        | Description                   |
| -------------- | ----------------------------- |
| `ls`           | List remote files             |
| `pwd`          | Show remote working directory |
| `cd directory` | Change remote directory       |
| `get file.txt` | Download a file               |
| `put file.txt` | Upload a file, if permitted   |
| `bye`          | Exit the FTP session          |

## 4. Docker — Container Inspection

Docker commands can help inspect and access containers in an authorized lab environment.

### 4.1 List Running Containers

```bash
docker ps
```

Show currently running containers.

To list all containers, including stopped ones:

```bash
docker ps -a
```

### 4.2 Access a Running Container

Using Bash:

```bash
docker exec -it <container_id> /bin/bash
```

Using Shell:

```bash
docker exec -it <container_id> /bin/sh
```

- `exec` — Execute a command inside a running container.
    
- `-i` — Keep standard input open.
    
- `-t` — Allocate a terminal.
    
- `<container_id>` — Target container ID.

## 5. SMB — Server Message Block

SMB is a network protocol commonly used for file sharing and related services, particularly in Windows environments.

### 5.1 List SMB Shares

```bash
smbclient -L //<ip-address>/ -N
```

- `-L` — List available shares.
    
- `-N` — Do not prompt for a password.

### 5.2 Connect to an SMB Share

```bash
smbclient //<ip-address>/workfiles
```

Connect to the `workfiles` share.

For a connection without a password prompt:

```bash
smbclient //<ip-address>/workfiles -N
```

### 5.3 Inspect SMB Shares with smbmap

```bash
smbmap -H <ip-address>
```

- `-H` — Specify the target host.
    
- Displays accessible shares and permission information, depending on the server's configuration.

### 5.4 SMB Enumeration with enum4linux

Basic enumeration:

```bash
enum4linux <ip-address>
```

More extensive enumeration:

```bash
enum4linux -a <ip-address>
```

Authenticated enumeration:

```bash
enum4linux -u <username> -p <password> <ip-address>
```

|Option|Description|
|---|---|
|`-a`|Perform a broader set of enumeration checks|
|`-u`|Specify a username|
|`-p`|Specify a password|

### 5.5 SMB Enumeration with Nmap

Enumerate SMB users:

```bash
nmap --script smb-enum-users.nse <ip-address>
```

Enumerate SMB shares:

```bash
nmap --script smb-enum-shares.nse <ip-address>
```

These scripts attempt to retrieve information exposed by the target SMB service. Results depend on access permissions and server configuration.

### 5.6 Locate Nmap SMB Scripts

Navigate to the Nmap scripts directory:

```bash
cd /usr/share/nmap/scripts
```

List SMB-related scripts:

```bash
ls smb*
```

Search for a specific script:

```bash
ls smb-enum*
```

### 6.1 Install a Debian Package

```bash
sudo dpkg -i filename.deb
```

- `dpkg` — Debian package management tool.
    
- `-i` — Install a package.
    
- `filename.deb` — Local package file.
    

If dependency errors occur, try:

```bash
sudo apt --fix-broken install
```

### 6.2 Start the Nessus Service

Start Nessus:

```bash
sudo systemctl start nessusd.service
```

Check its status:

```bash
sudo systemctl status nessusd.service
```

**Nessus** is a vulnerability assessment tool used to identify potential security issues in systems and network services.

## 9. Important Reminders

- **Identify the target first.** Confirm the IP address, subnet, and scope before scanning.
    
- **Understand the scan type.** Host discovery, port scanning, service detection, and vulnerability assessment serve different purposes.
    
- **Check the results.** An open port does not automatically mean a service is vulnerable.
    
- **Record useful evidence.** Save scan results, service banners, accessible shares, and relevant findings.
    
- **Protect sensitive data.** Do not expose real credentials, private files, or sensitive network information in shared reports.
    
- **Stay within authorized scope.** Run scans, enumeration, and access tests only on systems you own or have explicit permission to assess.
